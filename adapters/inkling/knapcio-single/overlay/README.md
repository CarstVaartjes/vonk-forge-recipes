# Speed overlays for SGLang (Inkling-2-Mini on GB10)

Import-time patches for the stock `lmsysorg/sglang:inkling-2-mini` image. Nothing in the image is edited: the
directory is mounted read-only into the container and put on `PYTHONPATH`; `sitecustomize.py` arms each package
only when its environment switch is set. With no switch set, nothing is imported and the engine runs exactly as
shipped. `scripts/launch.sh` sets the switches (`OVERLAY=0` turns all of them off).

A package whose patch target is missing or whose signature changed stops the server at start-up (exit 78) instead
of silently running the stock path.

## Layout

- `sitecustomize.py`: combined loader.
- `inkling_*/`: the packages; each has its own README with patch points, exactness argument, CUDA-graph safety
  and limits.
- `tools/`: GPU checks and microbenchmarks to run inside the image on a Spark with the server stopped
  (`gpu_check_qkvr.py`, `gpu_check_pico12.py`, `gpu_check_prefill.py`, `bench_moe_tiles.py`, `gpu_check.py` and `bench_draft.py` for the draft package,
  `build_hotvocab.py` for the hot-vocabulary draft, `gpu_check_hotbase.py` for its compact base logits,
  `bench_rnnhoist.py` for the Markov-walk hoist, `gpu_check_bv.py`, `gpu_check_fastprobs.py`,
  `gpu_check_fused_accept.py`, `gpu_check_fused_rsfix.py` and `bench_fused_accept.py` for the sampled accept,
  `gpu_check_rsfix.py` for `inkling_rsfix`, `gpu_check_certwide.py` for the certified wide head,
  `gpu_check_kv12s.py`, `gpu_check_settle.py` and `gpu_check_settle_lanes.py` for the packed KV store, `gpu_check_noexp.py` and
  `gpu_check_noexp_mask.py` for `inkling_noexp`, `bench_dfbytes.py` and `sweep_dfw8.py` for `inkling_dfbytes`,
  `gpu_check_dfaccept.py` for `inkling_dfaccept`).
- `tests/`: CPU unit tests (`tests/vcap`, `tests/draftbytes`, `tests/pico12`, `tests/prefill`, `tests/kv12s`,
  `tests/noexp`, `tests/dfbytes`, `tests/dfaccept`, `tests/dftail`; `tests/rsfix` runs under pytest), run them inside the
  image: `docker run --rm --entrypoint bash -v $PWD/overlay:/ov lmsysorg/sglang:inkling-2-mini -c "cd /ov &&
  python3 -m unittest discover -s tests/vcap"`.

## Bitwise checks and the assembler

Triton compiles PTX with its own bundled ptxas unless `TRITON_PTXAS_BLACKWELL_PATH` is set; importing SGLang's model
stack (as the server does) sets it to the CUDA 13.0 `/usr/local/cuda/bin/ptxas`. PTX leaves the accumulation order
inside BF16 `mma.sync` unspecified, so the same Triton kernel with `tl.dot` can produce different, though
individually deterministic, bits under the two assemblers (measured: one pfuse loop-message pass, 0 of 24 outputs
bit-identical at 8,192 rows across assemblers). Elementwise, reduction and CUDA-extension kernels are not affected.
Every GPU check that claims bit identity for a Triton kernel with `tl.dot` therefore runs under the serving
assembler: export `TRITON_PTXAS_BLACKWELL_PATH=/usr/local/cuda/bin/ptxas`, or import `sglang.srt.models.inkling2`
before the first kernel compiles, and point `TRITON_CACHE_DIR` at a fresh or check-specific directory so no binary
built with the other assembler is reused. Results are reported as "bit-identical under the serving toolchain".

## Writing a new overlay

Patch at import time through a post-import hook, check every target's signature, raise a `BaseException`
subclass on mismatch (SGLang's model registry swallows `Exception` during model imports), keep every per-step
action graph-safe (device buffers written before replay, no host sync), and log one line at start-up.
